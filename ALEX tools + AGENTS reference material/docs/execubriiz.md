# Execubriiz journals

Restart the desktop app after pulling this change: it adds a preload bridge,
Main-process workers and an additive local-database migration. In Journals,
choose **+ → Execubriiz**, name the journal and create it. Other journal templates
continue to use their existing folio viewer.

## Writing and the board

Opening words label each saved entry; the first entry of a session spans both
chip columns. Finish entry (Command/Ctrl–Enter) saves before clearing the composer.
New session finishes nonempty writing first. Opening an older entry in the editor
parks the current draft; finishing restores it. Returning without finishing puts
the abandoned edit in Trash rather than silently discarding it.

An entry opens the supplied mockup's modal: focus, ask, archive, copy, Highlight
cover, and open in editor. Selecting passage text before Highlight cover uses
that selection as the proposed chip label. Labels are never generated by AI.
Copy includes plain and rich text when supported by the clipboard.

The right side is a persistent working document. Its section formats are Themes,
Notes, Checklist, Sequence and Diagram; wording remains editable. Section controls
let you change format, reorder or keep a section in place. Idea controls let you
reorder, move between sections and remove ideas. Undo restores prior board
versions. Clear preserves entries and can itself be undone.

Structural AI changes appear as annotations on unchanged content. Apply or dismiss
them, or allow the frontmost proposal to apply after eight quiet visible-board
seconds. Editing the board holds the countdown; finishing an entry also applies
eligible proposals. Target revisions and protected editing regions are checked
again in Main before an AI change can commit. Stale proposals are removed.

Below 800px the board is a separate draggable, resizable companion. The journal's
own float keeps its existing centered 75%-height home position and dock/close
controls. Board visibility and companion geometry are separate from journal data.

## AI connection and support intensity

Choose profiles under **support**. Live and deeper work can use different configured
API models, without silently changing providers. OpenAI, Claude and Gemini use
the app's existing model/credential factory. The current Codex Subscription chat
connector is **not** used for Execubriiz: it lacks this workflow's scoped structured
tool interface. No web server or separate agent service is required.

Inbox-only performs saved-entry work and explicit prompts. Live chronicler adds
typing-time analysis. Full suite adds source-backed online reactions. Pause AI
does not stop writing or saving. Workers operate only while the app is running.

Live work is eligible after 1.2 seconds idle or six seconds of continuous writing,
with at least three seconds between live dispatches. A latest-only waiting live
request follows an active one. A journal has one board-writing worker at a time;
summaries and explicit prompts can proceed separately, up to three workers total.
Transient provider failures have bounded retries; other errors expose a retry
control and a useful reason. API token usage is reported, not invented dollar costs.

Each eligible saved entry gets a roughly 300-character summary (400 maximum).
Large sessions use session summaries and a latest-40 entry manifest, retaining
focused entries and bounded tools for reading/searching older originals. Initial
context budgets use conservative character estimates toward 6,000 live / 12,000
deeper-work tokens; these are not exact tokenizer guarantees. Retrieval exchanges
also have a hard character bound. Provider-reported token counts are logged.

Open may be used and cited. Invisible may inspire general ideas but is instructed
not to quote, identify or cite its source. Private content is excluded from the
AI entry reader and prompt construction. This is practical personal-app behavior,
not a claim of formally guaranteed semantic secrecy. Making entries private or
archiving them removes current source links without retracting board ideas.
Online research is withheld when the analysis context includes Invisible material.

## Implementation map

`src/components/journals/ExecubriizView.jsx` owns the composer, chips, entry modal,
support controls and floating companion. `ExecubriizBoard.jsx` owns typed-section
editing and annotations. The diagrams render declarative nodes/edges locally;
there is no AI-generated HTML/component code or downloaded diagram renderer.
`execubriiz-client.js` serializes local window commands; a revisioned snapshot
refresh keeps floating and panel surfaces aligned. All appearance is in the
Execubriiz region of `src/AppCombined.css` and follows the supplied mockups.

`electron/execubriiz/store.js` owns transactions and persistent journal commands.
`document.js` validates the ProseMirror-shaped document and its operation rules.
The canonical order is its child arrays, not a second rank store. Section/block
IDs and revisions support targeted changes instead of whole-document overwrites.
`runtime.js` schedules the distinct LangGraph roles. `search.js` adapts provider
web search into evidence-only reactions. `checkpoints.js` reuses the existing
serializer with journal-owned tables so internal jobs never create chat records.
Migration 016 and the matching Prisma models describe the new local tables.

## Verification status and hands-on scenarios

No server, build, lint, test runner or app launch was invoked for this change,
following the project's explicit rule. This is an implemented but runtime-unverified
feature, not a claim of completed visual or provider testing. Browser-only previews
without Electron cannot run this database-backed journal mode.

Exercise a long draft, finish it, create another entry and reopen the first in the
editor. Confirm the second draft returns. Try each chip modal action; archive and
restore both an entry and an entire journal. Trash's permanent deletion requires
confirmation, including bulk deletion of the currently shown items.

With a configured API profile, write until analysis arrives. Edit an idea while
another request is running; newer wording should remain. Convert a section, pin
its position, move ideas manually, dismiss a proposed conversion and undo a clear.
Try pause/resume, a disconnected provider, an app restart with queued saved-entry
work, a private entry and a private draft. Verify that private text does not appear
in provider requests. Check Log Panel for actions, requests, cancellations and
errors. Compare actual layout to the supplied mockups at wide and narrow widths.
