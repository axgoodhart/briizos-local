Journals float: drag, folio identity & editable titles
briizOS.Local · one focused session · 2026-07-24

Started by auditing half-applied hand-tweaks to the pop-out journal float, then built three connected features on top: click-and-hold-to-drag with a springy activation pulse, a folio-identity model so the folio+ button makes a genuinely new folio instead of another page, and an editable folio title in the page header. Each feature unblocked the next — titles are only safely editable because folios now have stable identity. The one real stumble was running an automated browser-verification harness against the user's live app, which they stopped immediately.

Loose Ends

imperfections & unresolved threads still standing in the app

Observed passively

  • Several panels crash the whole app when the renderer runs in a plain browser instead of Electron.NotesWidget.jsx:167 / InteractionPanel.jsx / TasksPanel.jsx dereference window.api unguarded; journals/api.js already shows the safe pattern
  • The root ErrorBoundary blanks the entire workspace when any single panel throws — no per-tile isolation.

Arose in this session

  • Legacy folios created before this session carry no groupStart marker; grouping still infers them correctly, but the two code paths (inferred vs. stamped) now coexist.computeGroups in JournalView.jsx handles both, but it's a subtlety a future editor must keep in mind
  • Folio title and folio type together still form the group key; renaming logic guards the collisions, but the key design remains fragile if a third grouping dimension is ever added.
