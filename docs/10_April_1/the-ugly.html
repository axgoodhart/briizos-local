Context-menu z-index bug fixed in two linesUser reported: hovering items in the ⋯ menu registered as hovering the card below. Diagnosed as a stacking-context leak — the menu was absolutely-positioned inside a card with no elevated z-index, so sibling cards drew on top and stole pointer events. Fix: add a menu-open class to the hosting card when the menu is open, and crown it z-index: 10 via one CSS rule. No portal, no JS, no drag-clamps.
